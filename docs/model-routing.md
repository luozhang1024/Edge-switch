# 模型路由

“设置 → 路由”包含模型 API 路由服务及原有的网络代理设置。模型路由按工作环境保存，与下载代理、SSH 网络代理分别管理。

## 接入工具

1. 在“模型服务”保存 API 供应商、模型 ID 和密钥。统一 New API 供应商可以加入多个工具的队列，由应用选择对应工具的原生接口。
2. 打开“设置 → 路由”，为 Claude Code、Codex、Gemini CLI 或 Grok 添加供应商并调整队列顺序。
3. 设置重试、超时与熔断参数，点击“保存路由设置”。
4. 启动路由服务，点击“接入当前工具”，然后重启工具会话。

本机配置在修改前自动备份。远程工具继续使用当前环境的独立配置目录，通过 SSH 反向转发访问电脑上的路由服务，板卡无需开放公网端口。请保持 Edge Switch、路由服务及 SSH 转发运行。程序重新启动后需要启动路由服务；监听端口修改后需重新接入工具。

“恢复供应商直连”会将当前工具配置为直接使用队首供应商，取消它的路由接入。操作会备份原配置。切换模型服务的当前供应商也会取消对应工具的自动路由接入；远程工具随后同步或启动时应用所选供应商。

## 故障转移

供应商按队列顺序尝试，每个供应商使用自己的模型和密钥。连接失败、408、429 和服务端错误触发重试及故障切换；其他请求错误直接返回，避免对无效请求重复计费。重试次数为每个供应商初次请求之外的最大重试次数，熔断可提前结束重试。

连续失败达到阈值，或达到最小样本量后错误率超过阈值，会打开熔断器。恢复等待时间结束后同一供应商只放行一个探测请求；连续成功达到恢复阈值后关闭熔断器。统计窗口在 1000 次尝试或设置的最小样本量（取较大值）后重置，熔断状态不跨应用重启保留。

流式首字节超时覆盖连接、响应头和首个数据块的等待；静默超时覆盖后续数据块之间的等待，0 表示禁用。非流式超时限制请求总时间。故障转移和整流重试共享该请求的等待预算。流式数据已经返回给工具后，不再向其他供应商重放该请求。

“记录请求用量”仅在内存记录本次程序运行的请求数、传输字节数与失败数，不保存请求正文、供应商密钥，也不代表供应商 Token 账单。返回本页面可刷新统计。

## 整流与优化

- Thinking 签名整流：Anthropic 返回签名错误时去掉不兼容的 Thinking 块。
- Thinking Budget 整流：明确遇到 1024 预算约束错误时修正预算与 max_tokens，保留 Adaptive Thinking。
- 图片降级：明确不支持图片的错误可触发占位文本替换；纯文本模型预判只针对内置的已知模型，不修改模型目录能力声明。
- Bedrock 优化器：只用于地址包含 `bedrock` 的 Anthropic Messages 兼容网关，可补充 Thinking 设置及系统提示词缓存标记。原生 AWS SigV4 认证、Converse 与 InvokeModel 接口暂不支持。

整流总开关控制请求修复，Bedrock 优化器拥有独立开关。每次向同一供应商发起请求，最多应用一次错误驱动的整流重试。

## 提示词跨工具复制

提示词条目的三点菜单提供“复制正文”“复制到其他工具”“删除提示词”。跨工具复制默认勾选当前程序支持的其他工具；各目标得到独立副本，不自动启用，不覆盖目标工具正在使用的提示词文件，后续修改互不影响。复制前检查全部目标，写入失败时尝试回滚已创建的副本。

启用中的提示词无法删除，菜单会提示先停用；后端同样禁止删除启用项。
