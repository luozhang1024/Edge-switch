# Edge SSH AI · 板卡 AI 工作台

Windows 中文桌面工具，在一个 Linux 账号下管理板卡连接、独立代理和 AI 编程助手。默认设备为 `FineHigh@192.168.0.168`，不保存 SSH 密码。

给同事安装：发送 **dist/installer/EdgeAI-Setup-0.15.0.exe**。安装到当前 Windows 用户，创建开始菜单及可选桌面快捷方式，支持卸载；不要求同事安装 Python。不打包本机配置、API Key 或 SSH 私钥，每台电脑独立生成环境标识。卸载保留用户配置和板卡文件。更新前请从托盘菜单或侧栏点击“退出程序”。

免安装使用：双击 **dist/current/EdgeSSHAI-0.15.exe**，也可以双击 **Start-Workbench.cmd**。需要 Windows x64、系统 OpenSSH；打开 VS Code 还需要安装 VS Code 并将 `code` 加入 PATH。首次使用需配置 SSH 密钥登录及核验主机指纹。若此前已打开工作台，先正常退出旧窗口再运行最新版。

0.15：官方卡片统一编辑、测试、验证、删除四个图标，删除置灰禁用。编辑窗口可保存名称、备注、官网，导入本人 Codex 的 OAuth auth.json；API Key 禁用。留空或 {} 保留已有凭据，不会登出。导入内容使用 Windows DPAPI 加密保存，启用时通过 SSH 同步到环境私有 codex-chatgpt-home/auth.json（0600）。同一导入快照不会覆盖 Codex 已刷新后的令牌；重新账号登录成功后丢弃本机旧导入，继续使用板卡新授权。修改凭据后需再次启用。编辑框重新打开默认显示 {}，不会自动显示保存的令牌。

官方“测试”：检查板卡至官方网页的连通与本机 CLI 的登录识别；网页 403 不等于 Key 无效，凭据识别也不保证订阅额度或推理成功。官方“验证”：经用户确认后，通过官方 Codex 在临时空目录发一条短请求，可能消耗订阅额度；只有完整模型回答才报告通过。不自动读取工程或使用工具，不记录原始 CLI 输出和令牌。官方网页测试与模型推理走不同端点，测试失败仍可显式验证。

账号登录在板卡终端运行官方设备码流程，浏览器授权在电脑上完成；板卡代理开关不控制电脑浏览器网络。若授权链接返回 unsupported_country_region_territory，请检查浏览器网络线路和官方地区支持；改 UI 或导入凭据不保证改变官方服务限制。导入凭据只应来自本人已登录的 Codex，不要分享 auth.json。

0.14：官方账号登录和切换统一到“模型服务”的 OpenAI Official 卡片；AI 工具页只负责安装和打开。默认卡片不要求填写 API Key，不可删除；授权完成后显示“使用中”。API 密钥和官方授权分别保存，切换时保留。状态检查不会切换服务或发送推理请求。

0.13：工作环境卡片新增“配置 SSH 登录”。同事首次使用，在终端核验主机指纹并输入板卡密码，程序仅向该 Linux 账号追加本机公钥，不保存密码或复制他人私钥。成功后自动保存本机私钥路径。首次授权最多等待 5 分钟；失败可重新点击。已运行的 Harness/代理请先停止再修改环境身份。

模型服务默认提供 **OpenAI Official** 官方账号卡片，与自定义 API 一起切换。先安装该环境的受管 Codex，鼠标移至官方卡片点击“启用”：已登录时直接切换，未登录时打开编辑窗口，可导入凭据或点击“账号登录”使用设备码授权；卡片“测试”检查连通与登录，“验证”确认后发送最小推理。在弹出终端查看授权网址与设备码，在本机浏览器授权。若账号关闭设备码授权，请在官方账号设置启用，或通过远程 Codex 插件官方登录入口授权。然后点击“打开 VS Code”或“打开终端”。设备码登录最多等待 10 分钟。工作台只在 CLI 确认后报告已登录；没有自动发送推理请求。

官方登录使用环境专属 `codex-chatgpt-home`，保留 API 的 `codex-home` 与密钥；启用列表中的某个 API 后，再次打开工具应用配置。官方账号的权限和额度由 OpenAI 的账号、套餐和服务可用性决定，不等同于第三方 API 余额；网络仍需能访问官方服务。启用某个 API 会自动切回 api。不同电脑独立授权，不随安装包分发账号令牌。两台电脑可以共用 Linux 账号，但请各自完成 SSH 和 ChatGPT 授权。

0.12：VS Code 打开改用复用窗口，不再等候新连接日志，避免重复打开时额外等待 75 秒。返回消息只确认已发送请求、配置认证已完成，不将命令成功误报为新隧道已建立。Harness 打开时先检查并接回现有服务；关闭网页不会停止后台服务。现有工程或网络与表单不同时，显示差异，允许选择保留任务打开现有服务、明确停止并按新配置重启，或取消。仅打开网页不会自动重启服务。

0.11：工具版本列表在独立后台线程更新，不占用全局任务锁，可同时编辑环境、测试 API 等。列表缓存在本机一天，重新打开立即使用缓存；可手动刷新。网络不通时保留已有版本。

API 编辑默认勾选 Windows 加密保存，重启后保留 Key，可主动取消选择只在本次会话使用。已同步到板卡的服务即使本机没有保存 Key，也能在测试/验证时安全复用板卡凭据；服务 ID 和 API 地址必须匹配，密钥不返回本机。未保存过、已换服务或换地址的密钥仍需要重新填写。

点击窗口关闭按钮会缩到系统托盘，代理隧道和 Harness 连接继续运行；双击托盘图标或右键“打开工作台”恢复，右键“退出程序”或侧栏“退出程序”才结束连接。图标是否收进任务栏右侧隐藏区域由 Windows 设置决定。此行为替代旧版本的“关闭窗口立即退出”，不是系统服务或开机自启。

代理路径是板卡工具 → SSH 反向隧道 → 本机 FlClash HTTP/mixed 端口 → 外部 API。启用代理的工具依赖电脑、FlClash 与工作台在线；退出程序、电脑关机或代理离线会中断这条线路。可直连的 API 不必开启代理。

新工作台不引用 `LPB3568codex/` 旧项目目录，受管工具位于板卡 `~/.local/share/edge-ssh-ai/<标识>/`。旧项目可先归档；确认同事的旧快捷方式、Shell 脚本或 VS Code 配置不再指向它后再清理。不要连带删除共享 `~/.codex`、VS Code Server 或工作台专属数据目录。

0.10：侧栏移除环境下拉和重复新建按钮，默认打开工作环境。页面按“工作环境 → 代理网络 → AI 工具 → 模型服务 → 设备总览”排序；顶部显示当前环境，代理按需配置，已有直连可以跳过。进入 AI 工具页自动获取已发布版本，下拉选择后安装；默认选择上游 latest，保留已保存版本，读取失败可刷新。版本列表由本机获取，使用“运行环境下载 / 版本查询”代理选项；可选版本不等于已验证兼容，安装阶段仍检查运行条件。环境与 API 弹窗居中于主窗口，并补偿 Windows 标题栏偏移。侧栏底部新增 luozhang。

0.9：“工作环境”改成卡片列表，使用配置环境.png 图标，支持弹窗新增、编辑、连接测试和删除，点击“使用”切换；侧栏下拉保留快捷切换，重启记住上次使用环境。每个环境独立保存设备、工程、代理与 API。新增后不会自动切换；切换只改变当前操作目标，不中断其他环境的网页、后台任务和 VS Code。存在本工具管理的连接时，修改连接信息或删除环境需先停止该环境的 Harness 并断开代理；删除不清理板卡文件，也不关闭已有 VS Code。默认窗口缩小为 1040×700，最小 980×640，侧栏及卡片间距收紧，页面仍可滚动。

0.8：API 卡片新增“验证”图标，确认费用提示后发送最小推理请求；“测试”仍只检查连通性与模型列表。图标悬停显示两字提示：添加、启用、编辑、测试、验证、删除。VS Code 按钮使用 Vscode.png，模型服务页也可直接打开编辑器。打开前先列出已安装的 Remote SSH 扩展，已安装则跳过市场安装命令，减少不必要的网络依赖；缺失时才联网安装。扩展安装、板卡 SSH、模型 API 各自可能失败，不互相代表成功。

0.7：模型服务只保留 API 卡片。鼠标移至未使用的卡片时显示蓝色“启用”及编辑、测试、删除图标；点击启用会同步到板卡，成功后变为灰色“使用中”，失败保留原使用状态。使用中的卡片常驻显示编辑、测试和删除图标，也可以删除最后一条 API。编辑、测试、删除、启用和添加采用 `image/` 内提供的图片。加号直接使用原图，透明背景，不另加边框；点击打开独立小窗口，填写后保存，取消不会创建空记录。编辑也使用弹窗，可读取模型列表。测试图标检查 API 连通性和模型列表，不发送付费推理。编辑当前服务的连接、模型或密钥后，需要再次启用；已打开的 VS Code 仍需 Reload Window。

顶部全局保存按钮已移除。设备与代理等设置在停止输入约 0.7 秒后自动保存，右上角显示保存状态；无效的地址或端口不会覆盖上次有效配置。API 编辑仍在弹窗中点击保存确认，取消则放弃修改。

0.6：模型服务改为多 API 卡片，可添加、命名、编辑、删除和选择；每个 API 分别保存模型、协议与加密凭据。点击卡片“选择”切换编辑目标，再点击“同步到 Codex”应用到板卡并验证扩展 CLI 登录，或“同步并打开 VS Code”。已打开的 VS Code 需执行 Reload Window，终端需重新打开，才会读取新配置。Chat 协议可保存、测试，但 Codex 同步要求 Responses。Harness 模型仍在其网页配置，不会自动接管。

支持范围：Linux ARM64 / x86_64、glibc ≥ 2.28；板卡需有 SSH 服务、Python 3.8+、可写用户目录，以及工具安装所需的空间和网络。不是所有 Linux 板卡均可直接使用：ARMv7、RISC-V、musl/Alpine、Android 或缺少完整用户空间的系统需要额外适配；本次实机验证为 LPB3568 ARM64 / glibc 2.31。不同发行版、VS Code Server 与上游 AI 工具还需满足各自依赖。

## 使用

1. 在“设备与连接”核对 IP、用户名、工程目录和私钥。点击“检查连接”。后台使用现有 SSH 密钥；首次连接可打开 SSH 终端核对主机指纹。需要密码时在终端输入，工作台不记录密码；后台安装和诊断需要可用的密钥登录。
2. 在“代理网络”为 Codex 和 Harness 分别选择连接方式。需要电脑代理时，启动 FlClash 并填写 HTTP / mixed 端口；使用工具时自动连接，也可手动点击“连接代理”。运行环境下载和版本查询单独选择，工具安装使用各工具的网络设置。
3. 在“AI 工具”安装独立 Node.js 24，查询 npm 版本，然后分别安装明确版本的 Codex / Harness。下载和安装期间查看底部状态，完成后显示结果；失败保留安装阶段目录，不会将其选为当前版本。
4. Codex：在“模型服务”填写支持 **Responses** 的 API 地址、模型和 API Key，可先测试；再点击“同步插件并打开 VS Code”。需要终端时，在“AI 工具 → Codex”点击“打开终端”。两者使用工作台独立的 `CODEX_HOME`，不修改原来的 `~/.codex`。
5. Harness：点击“打开 Harness 网页”。在网页 **Settings → Models** 配置 DeepSeek 或自定义 API，选择工程目录后开始使用。它的模型配置由 Harness 自己管理，不会自动复制工作台表单中的 Key。当前上游为开发预览版。
6. 打开 VS Code 时检查 Remote SSH 和远程 Codex 扩展。已安装的远程 Codex 直接复用；缺少扩展时尝试安装，安装失败会报错。工作台把独立启动入口配置到此工作环境专属的本机 VS Code 设置中。请使用新开的窗口；旧窗口仍显示未登录时，保存文件后执行“Developer: Reload Window”，或从工作台重新打开。

Codex 的 API 登录与 ChatGPT 订阅登录是不同方式：填写 API Key 后使用 API，不会显示为 ChatGPT Plus 账号。插件内的 ChatGPT 账号信息、部分账号专属功能可能仍不可用。同步会验证扩展 CLI 的认证状态，不自动发送付费推理请求；供应商额度与模型能力使用“测试推理”单独检查。

运行日志默认收起，点击底部“运行记录”展开。

可以创建多个“工作环境”用于不同设备或供应商。同一 Windows 用户仅运行一个工作台；从列表切换环境会保存当前表单。

## 单账号使用边界

- 每台电脑首次启动生成独立 ID。每个工作环境在板卡使用独立目录；不要把本机配置文件复制到另一台电脑后同时运行，否则会复用其身份。
- 代理使用 SSH 自动分配的板卡回环端口，不占原来的 7890。停止操作仅处理本程序创建的 SSH 子进程。
- Harness 只监听板卡 `127.0.0.1`，通过独立 SSH 本地转发访问；支持其临时访问令牌与 Cookie，本地鉴权及就绪检测成功后才打开浏览器。后台模式退出时仅关闭网页转发；关闭后台选项后退出则结束该环境的服务。停止服务前核对 PID、启动时间、用户和脚本路径，不按进程名批量结束。
- 工作台不批量关闭 VS Code、不删除共享 `/tmp` 文件、不改 `.bashrc` / `.profile`，不自动重启共享 VS Code Server。原来的修复入口仍单独保留。
- 多人同时使用时应统一使用新入口；旧 `LPB3568codex` 的切换和停止脚本仍有批量结束进程、覆盖共享配置的行为，新工作台无法阻止这些外部操作。
- VS Code Server 仍共用账号。工作台打开的独立 VS Code 本机设置通过 `chatgpt.cliExecutable` 指向专属启动器，为插件后台设置独立的配置、认证与代理；其他入口打开的 VS Code 不会自动采用它。该扩展设置目前标为开发用途，后续扩展升级后应重新同步；启动器使用插件自带的 CLI 以匹配其版本，不修改插件文件。
- 同一账号可以访问彼此的文件，也共享板卡 CPU、内存和磁盘。这是配置与连接管理，不是安全隔离。
- 隧道断开后自动重连并复用原端口，本机代理暂停后也会等待恢复。若原端口被其他程序占用，会报告失败；不会偷偷换端口使运行中工具失效。尚未实现配置回滚和一键 VS Code 修复。

## 数据和安装位置

本机数据：`%LOCALAPPDATA%\EdgeSSHAI`，包含设备配置、下载缓存、工作台专属 VS Code 设置。勾选保存 API Key 后通过 Windows DPAPI 加密，绑定当前 Windows 用户；未勾选则不在本机配置中持久保存。

板卡数据：`~/.local/share/edge-ssh-ai/<工作环境标识>/`。

- `runtime/`：独立 Node.js 24.11.0，不替换系统 Node。安装包经本机和板卡 SHA-256 校验；当前支持 ARM64 / x86_64、glibc ≥ 2.28。
- `tools/<工具>/<明确版本>/`：npm 工具版本；成功执行 `--version` 后才更新 `current.json`。
- `codex-home/`、`harness-home/`：各工具独立设置与状态。
- `launch.json`：Codex 启动所需的 API Key 和连接配置，板卡文件权限 600；父目录限制为当前用户。
- `codex-home/auth.json`：Codex 的 API 认证文件，权限 600。
- `run-ide-codex`、`ide-runtime.json`：VS Code 插件专属入口及所用的扩展 CLI 路径，不包含明文密钥。若插件升级更换路径，从工作台重新同步。

API 请求在板卡执行，Key 经 SSH stdin 传递，不放在进程命令行。本机 API 测试不跟随重定向、不展示服务器错误正文。测试支持 Chat Completions / Responses；模型列表、最小推理分别判断结果，尚未验证流式与工具调用。最小推理会提示可能产生调用费用。

卸载工作台前先关闭它；根据诊断中的 HOME 和工作环境 ID 确认专属路径后再手工清理。不要删除整个 `~/.codex` 或 `~/.vscode-server`。
