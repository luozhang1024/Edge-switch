# Edge Switch v1.0.2

修复 VS Code Server 下载流程缺少代理配置、进度与缓存管理的问题。此次日志已明确报告 `LocalDownloadFailed / Failed to fetch`，SSH 登录已经成功。

## 变化

- 打开前检查电脑实际 VS Code commit，准备对应 ARM64 / x64 Linux 服务端。
- 服务端由工作台通过微软官方 HTTPS 地址下载，使用“代理网络”的电脑代理开关和端口；不再依赖 Remote - SSH 在后台长时间无进度地下载。
- 最多 6 路分块下载，显示大小与百分比，保留完成分块用于重试。单块下载限时 120 秒，下载阶段总限时 10 分钟。官方 SHA-256 校验成功才生成缓存；后续环境可以使用缓存，已安装的匹配版本跳过下载及上传。
- 上传后在板卡再次校验，解压到临时目录，检查 commit 和 Node 可执行性，再放入目标目录。拒绝越界压缩包路径；不覆盖已有不完整目录。
- 每台电脑的每个环境使用自己的 VS Code Server、扩展、启动环境与安装锁。原有共享 `~/.vscode-server` 保留，不删除锁、不终止同事的进程。首次需要在独立目录安装扩展，会增加磁盘使用。
- 电脑 VS Code 的 HTTP 代理与板卡启动代理分别使用本机端口、SSH 隧道端口。专用启动脚本清除继承的旧代理，再设置此环境代理。
- 远程窗口先打开，再准备 Codex 扩展；连接诊断识别等待下载和 `Failed to fetch`，提供具体原因。

## 升级使用

1. 保存文件，关闭本次卡住的远程窗口。
2. 安装新版；保留原环境与 API 配置。
3. 确认 FlClash 已运行，在“代理网络”中检查电脑代理开关与端口。
4. 点击“打开 VS Code”，关注工作台阶段进度。下载失败后可再次点击，复用完成分块。

## 验证与限制

- Windows 回归检查覆盖缓存校验、分块合并、窗口与扩展安装顺序、凭据隔离和下载错误诊断。
- 实机 Linux 检查覆盖独立目录安装、已安装检测、坏哈希拒绝、压缩包路径越界拒绝。
- 实测电脑直连和当前 FlClash 线路下载微软服务端均较慢。VS Code 1.145.1 的当前 ARM64 包为 223,295,195 字节（约 213 MiB），完整下载与真实编辑器连接尚未验证成功；不能据此声称网络问题已经消除。
- 下载缓存不保证远程扩展市场、模型 API 或 SSH 局域网连接可用。匹配版本安装完成后无需再次下载，VS Code 更新可能触发新版本准备。
- 多个独立 VS Code Server / 扩展宿主会增加板卡内存使用；4 GB 板卡应控制同时打开的环境数，工程目录应选实际项目，避免 `/` 全盘扫描。

## 架构取舍

保留 Python 桌面端与按需 SSH 任务，优先把服务端准备、网络线路、连接阶段和环境状态明确管理。当前问题来自部署和网络链路，单独替换为 Tauri、Electron 或更换 UI 语言无法解决。板卡继续按需运行，避免仅为管理而常驻额外 Web 服务或容器。
