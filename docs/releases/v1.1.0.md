# Edge Switch v1.1.0

系统 VS Code 自动更新会改变 Remote SSH 所需服务端版本。v1.1.0 改为使用工作台管理的固定编辑器副本，避免日常更新反复触发板卡下载。

## 功能

- 首次打开时从电脑已有 VS Code 创建独立副本，不下载 Windows 编辑器，不修改或降级系统 VS Code。
- 后续启动从固定版本配置读取 `Code.exe`，不再重新选择 PATH 中被更新的版本。副本损坏时明确报错，不静默切换到新版本触发下载。
- 工作台专属窗口设置 `update.mode=none`，关闭扩展自动更新。Remote SSH 扩展使用独立目录；存在本机已安装的 Remote SSH 扩展时复制程序文件，不复制其用户状态。
- AI 工具页新增“编辑器版本”，可主动选择当前系统版本或另一套已有的 `Code.exe`。切换影响本机各环境的后续连接；切换前请保存并关闭工作台远程窗口。版本切换可能需要新的服务端和扩展。
- 首次部署新环境时检查板卡共享服务目录及其他工作台环境，存在同一 commit 的可运行服务端则复制程序文件到独立目录，跳过下载和上传。不会复用不匹配的旧 commit，也不复制凭据、扩展、安装锁。
- 保留 1.0.3 的断点续传、官方校验与手动导入功能。复制 Windows 副本不包含便携版 `data`、项目文件、卸载器或密钥文件。

## 存储与边界

- 固定编辑器：`%LOCALAPPDATA%\EdgeSSHAI\editor\<commit>`。
- 本机选用版本：`%LOCALAPPDATA%\EdgeSSHAI\editor\selected.json`。
- 服务端仍位于板卡当前环境的 `vscode-server` 目录。
- 编辑器副本、独立扩展及板卡服务端副本均会占用额外空间。不会自动清除旧版本。
- 固定版本避免自动更新触发下载，不代表可以绕过 Remote SSH 的版本匹配要求。缺少匹配文件的首次部署仍需获取一次。
- 固定版本不会自动收到安全和兼容性修复，需要主动安排升级。上游扩展及 API 服务仍有各自的网络要求。
- Codex 终端和 Harness 不需要 VS Code Server，可独立使用。

## 验证

- 在本机从现有 VS Code 创建实际可运行的副本，再次解析版本一致。
- 实机 ARM64 板卡从已安装的旧版本服务端向全新临时环境复制程序文件，`ready=true`、`reused=true`，重复检查通过；测试后仅删除临时环境。
- 测试固定版本忽略系统更新、复制排除便携数据与卸载器、失败不改变选用版本；板卡凭据和锁隔离测试通过。
- 当前电脑版本为 `6bab64e2d12b04d04c0d99c27ff166023efd1dda`，板卡现有可运行旧版本与其不匹配。新版本完整下载及真实 VS Code 编辑器连接尚未验证成功，不能把固定策略视为已修复该次首次部署的网络问题。
