RK3568 VS Code SSH 一键修复

目标：FineHigh@192.168.0.168

怎么使用
1. 先保存远程文件，并确认同事当前没有依赖此账户 VS Code 远程终端的任务。
2. 双击桌面“RK3568一键修复”。8 秒内可关闭窗口取消。
3. 等待窗口显示“修复完成”。工具会打开新的 VS Code SSH 窗口。
4. 如有需要，在新窗口中选择“文件 → 打开文件夹”，打开 /home/FineHigh。

只想检查而不修改：双击桌面“RK3568只读诊断”。
如有报错，不要只截最后一行；保留本目录 logs 中最新的日志。

下载规则
不是每次连接都下载。完整且匹配当前 VS Code 版本的服务端会直接复用。
只有服务端缺失、损坏或 VS Code 升级后版本不匹配时，工具才下载匹配版本。
下载使用官方 HTTPS 地址，安装前在电脑和板子上分别核对官方 SHA-256。
安装包保存在 cache。再次修复同一版本时，会校验并复用缓存。
首次下载安装可能需要数分钟，速度取决于网络。

代理处理
不会修改同事的 .bashrc、.profile，也不会修改 Windows 的系统代理。
不会修改本机 VS Code 的 http.proxy。
在板子 ~/.vscode-server/server-env-setup 中加入有边界标记的代理检查块：
仅在 VS Code 服务启动时，跳过连接不到代理地址的环境变量。
能连接到的代理继续保留；这不代表代理认证和外网线路一定正常。
如果远程 VS Code 的 http.proxy 指向不可连接的地址，会备份后在远程设置中清空它。
该远程设置覆盖值会一直生效；以后若要让 VS Code 使用新的代理，
请在“远程设置”中填写板子可以访问的代理地址，或删除 http.proxy 覆盖项。
可用代理通常不影响 SSH 登录；坏代理主要影响安装包和扩展下载。
板子的 127.0.0.1 是板子自身，不是电脑。使用电脑代理需使用可达地址或有效 SSH 转发。

修复范围
检查 SSH 登录、ARM64 架构、磁盘空间和当前版本服务端。
使用 flock（可用时），避免旧硬链接安装锁长期阻塞。
当前版本服务端缺失时，通过临时目录安装，旧目录会保留为备份。
仅对 FineHigh 账户当前 VS Code 版本的服务端发送正常退出信号。
不会强杀业务程序，不会清空整个 .vscode-server，不会删除工程。
重启会断开此账户对应版本的 VS Code 连接，远程终端任务可能受影响。

备份与日志
本机/远程被修改的配置会在同目录留下 .backup-ssh-时间戳 备份。
不完整服务端保存在原目录旁的 .incomplete-backup-时间戳。
安装锁归档在 ~/.vscode-server/repair-backups/。
工具日志位于 D:\Tools\RK3568-SSH-Repair\logs。
要撤销配置修改，先保存工作，然后将所需备份复制回原文件；重连使其生效。

不能自动修复的情况
板子断电、网络不通、IP 改变、SSH 服务未启动、登录密钥失效或主机指纹变化。
这些情况会明确报错；工具不绕过身份验证，不接受陌生主机指纹。
代理服务器能连接但自身认证或外网线路失败，也需要修复代理本身。

文件位置
Start-Repair.cmd：双击修复入口。
Diagnose.cmd：只读诊断入口。
repair.py / remote_repair.py / jsonc_utils.py：工具源码。
test_repair.py：配置保留、备份和下载校验的测试。
依赖本机 Python、Windows OpenSSH、curl 和 VS Code；板子需有 Python3 和 tar。
桌面快捷方式指向本目录，移动或删除本目录会导致快捷方式失效。
